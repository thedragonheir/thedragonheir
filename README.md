My passion is exploring and understanding what goes on "under the hood" of older games and software.

To achieve this, I analyze compiled code, identify functions and data structures, and work to understand how the original systems operate. From there, I try to reconstruct their behavior into clear and readable source code. I then verify my work byte by byte, aiming to reproduce the original game's machine code as closely as possible and preserve the original implementation with the highest possible degree of fidelity. 

**Experience**
- Reverse engineering old game programs to understand how they were made
- Taking decompiled programs apart to reconstruct their C++ code
- Analysing engine internals, memory layouts and related data structures
- Understanding and rebuilding old networking technology and backend services

**Involvement**
- Legacy software rebuilds -- This involves a lot of time being spent in reverse engineering and then coding up old systems
- Multiplayer infrastructures -- Creating or restoring protocols and other types of services that old online multiplayer games utilized
- Unreal Engine -- Making a gameplay system, camera movement, and controls similar to those of an RTS game
- Tools -- Creating little utilities that assist in debugging, analysing, and building code

**Languages & tools**

`C++` `C` `Java` `Python` `Visual Studio` `Ghidra` `Unreal Engine` `Git` `Windows`

I love software that leaves room for curiosity. Older games are especially interesting to me because they bring graphics, networking, simulation, AI, memory management and large native codebases together in one place.

For me, reverse engineering is not just about getting something to work. I enjoy trying to understand what the original programmers intended, how their systems were designed, and then expressing that understanding again as clean, readable source code.
